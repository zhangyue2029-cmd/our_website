# 去向 · 两个专业入口版

本轮按要求只调整前两页：保留花朵绽放与共享胶囊转场，第二页只显示「汉语言文学」「新闻传播」。点击「探索该专业」直接进入原有学习领域，不再增加文学/理学等门类和额外专业列表页。

## 本地运行

进入本目录，使用 Node.js 18+：

```bash
node _server.cjs
```

打开 http://127.0.0.1:8124/ 。无需安装依赖。Windows 可使用「启动预览.cmd」。

## 原功能保留

两个入口对应原有的 `chinese` 和 `journalism` ID。专业数据、独立学习领域、职业关联、14 个职业、题库、市场示例数据、计分、职业星系和四部分画像保持原样。浏览或切换胶囊不会清除测评；确认进入不同专业时继续使用原来的回答重置规则，同专业再次进入保留回答。

`#/home` → 花朵共享转场 → `#/choose` 两专业胶囊 → 对应 `#/focus` → 原有职业探索流程。旧的 `#/majors` 链接兼容回到两个胶囊入口。旧分类状态会归一到当前已有专业或默认汉语言文学，不会因此重置测评。

前两页继续支持鼠标、左右键、Home/End、横向手势及 prefers-reduced-motion。后续页面的渲染函数逐字节核对未变，21 个受保护业务与样式文件一致性检查通过。

## 访客职业分析

职业详情中的「填写个人背景」可保存本地草稿。「完成填写」后，网站按已发布的招聘要求对照经历中的文字线索，生成经历关联、待补证据和具体行动建议。规则在本站服务器运行，无需模型、密钥或第三方接口。

相同输入和规则版本会得到相同结果。文字匹配只能提示可整理的经历线索。当前资料用于职业探索，暂不计算证据覆盖率。访客可直接生成报告，登录用户可选择保存。

## 账号与分享圈子

站点配置 PostgreSQL 后，「我的」支持本地用户名账号与私人背景档案，「分享圈子」支持访客筛选和登录发帖。应用使用 `QX_DATABASE_URL` 连接数据库。安装依赖使用 `npm ci`，按顺序应用 `db/accounts/001_accounts.sql`、`db/accounts/002_reports.sql` 后，按编号应用 `db/community/` 下的迁移。部署应由 HTTPS 反向代理访问本地 Node 服务，账号会话使用 Secure Cookie。

运行 `npm run test:accounts` 可在临时 PostgreSQL 中验证账号会话、背景归属、发帖权限、搜索和匿名规则。招聘数据库仍由独立迁移维护。

登录用户可在提交分析前选择保存报告。账号页为每个职业显示最新一次成功保存的报告。
