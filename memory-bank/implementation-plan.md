# 去向 V2.0 实施计划

依据 [产品设计文档](design-document.md)和[技术栈选型](tech-stack.md)。按编号执行，每步完成后运行对应测试，记录环境、测试数据、实际结果和通过状态。测试失败时先修复再继续依赖该结果的步骤。遇到源码、授权、服务或产品参数缺失时，记录具体阻塞并继续独立步骤。测试环境使用隔离账号和数据，真实服务冒烟测试使用获准的测试凭据和非敏感输入。

## 一、确认现状与实施边界

1. **建立 V2.0 源码基线**  
   **指令**：使用已确认的网站初版，即同仓库的 master 分支，作为增量开发基线。本次已核对的初版提交为 e6faf3c27357da90cf13a6d6ebc0c766246612d2。将当前工作区的 README 文档入口、memory-bank 和 V2.0 PRD 带入开发分支，保留初版已有文档，并记录实际使用的提交及启动入口。  
   **测试**：核对开发分支包含初版基线提交，README 中的项目文档链接均有效；从基线启动网站并进入现有职业星系，为下一步记录回归结果。

2. **建立旧站回归基线**  
   **指令**：盘点路由、星系组件和动效、鉴权、持久化及部署方式。记录旧职业链接和专业映射，标记每项保留、调整、新增或待核实。  
   **测试**：分别从新闻传播学、汉语言文学及其他现有专业走通类别、职业、详情路径，记录职业标识和星系交互结果。

3. **确定技术方案**  
   **指令**：优先沿用成熟的前端、认证和后端。若现状只有静态前端，评估 Next.js、TypeScript 和 Supabase；记录新增依赖、迁移成本、保留方式和回滚点，再确定选型。\
   **测试**：在隔离环境做最小验证，确认选定方案能加载旧星系、读取旧职业标识，并完成一次现有或拟用登录流程。

4. **建立测试环境**  
   **指令**：配置独立开发与测试环境，准备访客、两个普通账号和管理员。登记人工导入、规则版本和存储的配置项、区域、配额和数据处理条款。\
   **测试**：运行构建和现有测试，验证各测试身份可建立会话；测试写入仅出现在测试数据环境，服务端密钥不出现在浏览器和构建产物中。

## 二、职业目录与招聘资料

5. **校对目录映射**  
   **指令**：沿用旧标识修正专业、类别、职业与星系节点之间的对应关系，核对设计文档列出的新闻传播学十一职业。  
   **测试**：逐一核对十一职业和旧链接；验证汉语言文学无错配、其他专业的映射与基线一致。

6. **登记招聘来源**  
   **指令**：登记用户提供的资料名称、批次和已附出处。保留已知的证据等级；此次用户提供的资料按确认口径直接进入人工归纳流程。\
   **测试**：分别导入一条附原始链接和一条只附文档位置的资料，确认两种出处均可在候选索引中追溯。

7. **保存候选岗位及结构化要求**  
   **指令**：记录职业、岗位类型、招聘性质、企业类型、原始链接、日期、岗位状态及候选审核状态。将要求类别、重要性和原文出处关联到岗位。  
   **测试**：导入一条缺少发布日期的样本和一条带原文引用的样本，核对未知日期明确保留、要求可回溯、候选记录未对外展示。

8. **验证人工批次导入**\
   **指令**：将人工提供的文件整理为候选批次，校验职业标识、通用要求和出处，导入候选区。\
   **测试**：验证完整批次可导入。缺必填字段或引用不存在的出处时拒绝整个批次。

9. **处理重复与更新**  
   **指令**：按来源标识或规范链接识别重复，识别内容变更并生成待审核更新。  
   **测试**：重复导入同一记录只保留一条候选；修改一条要求后可审查变更，线上旧版仍可读取。

10. **建立审核与版本发布**  
    **指令**：让获授权管理员审核、退回或撤回岗位及要求，记录原因、操作者和时间。发布后生成可追溯的数据版本，并提供回退。  
    **测试**：用候选、退回、已发布三类记录检查公开查询和分析查询的可见性；回退后核对公开版本和审计记录。

11. **处理人工更正与过期复核**\
    **指令**：收到更正、失效或撤回通知后，由维护人员提交新版或撤回当前发布。保留历史版本与时间说明。\
    **测试**：验证更正批次审核前旧版仍可读；撤回后不再对外显示撤回版本，历史记录可在后台追溯。

## 三、职业探索

12. **分开品牌首页与探索入口**  
    **指令**：建立独立品牌首页，以大标题、简洁几何装饰和「开始探索」入口为主，提供职业探索、分享圈子、我的导航。  
    **测试**：访客从首页进入独立专业选择页，再用浏览器返回；桌面和手机均可操作主入口。

13. **实现专业与类别选择**  
    **指令**：使用编辑式列表和色块展示目录，以文字或标记表达选中状态，提供返回与无数据提示。  
    **测试**：切换两个专业，核对类别随专业变化；测试空目录、键盘选中和返回后的路径状态。

14. **增强原职业星系**  
    **指令**：保留节点布局、连接、微闪、鼠标聚焦和展开交互；突出选中类别，同时让所有十一节点可进入，提供键盘与触屏等效操作。  
    **测试**：选择一个类别后数出十一节点，用鼠标、键盘和手机触屏分别打开节点，确认弱化节点也能进入正确详情。

15. **建立职业详情标签**  
    **指令**：依次提供工作职责、企业差异、招聘要求三个顶部标签，默认显示职责。保留当前职业、标签和合法筛选状态。  
    **测试**：直接打开指定标签，切换后刷新，再从错误职业链接进入；确认状态可恢复、错误链接有提示且不串数据。

16. **展示招聘共性要求和样本**  
    **指令**：在招聘要求标签中展示选定范围的归纳要求及可展开样本，标注来源、日期、审核结果和历史状态。  
    **测试**：从一条共性要求追溯到原样本；对照校招、实习、社招及过期记录核对标签，确认待审数据不可见。

17. **增加两级分析目标选择**  
    **指令**：按已发布数据提供岗位类型和可选企业类型，显示覆盖情况；允许用户跳过测评，直接浏览其他职业或圈子。  
    **测试**：从两个企业类型切换筛选，验证样本变化；提交失效范围时提示重新选择，跳过测评时 分析调用数为零。

## 四、背景测评与报告

18. **建立五类背景输入**  
    **指令**：在同一页提供课程、比赛与项目、实习与社会实践、作品与作品集、技能与工具，以及自由补充。支持条目增删、选填详情及调整分析范围。  
    **测试**：只填一门有效课程即可通过校验；全空、空白字符或失效范围被阻止；编辑、切换范围和离开页面均不触发分析。

19. **实现访客暂存**  
    **指令**：将访客草稿最小化保存在当前浏览器，提供清除入口和数据丢失提示。登录前保持草稿与账号数据独立。  
    **测试**：同一浏览器刷新可恢复草稿；另一浏览器看不到；主动清除后刷新不可恢复。

20. **接入登录及上下文恢复**  
    **指令**：复用审计确认的认证方式。访客发起需登录操作时，保存目标页面和动作；登录后仅在用户同意时同步访客草稿。  
    **测试**：分别从收藏、评论和私信入口触发登录，确认回到原目标；分别测试同意与拒绝草稿同步，核对账号数据。

21. **实现一次有效提交对应一个分析任务**  
    **指令**：以「完成填写」为唯一首次触发动作。服务端校验范围和输入，记录任务状态，支持离开后恢复及失败后重试。  
    **测试**：同时提交两次相同请求并刷新返回，核对只创建一个任务和一次有效规则计算；失败重试后状态可恢复。

22. **固定分析输入与样本充分性规则**  
    **指令**：锁定职业、岗位与企业范围、已发布样本、用户背景和算法版本。以去重、招聘性质、企业多样性和要求覆盖度确定可计算条件，待产品和内容审核确认阈值后启用。  
    **测试**：准备充足、稀少、无可用要求三种范围，逐一检查判定；发布新版资料后验证在途任务仍使用原快照。

23. **接入规则分析并验证引用**\
    **指令**：用服务端版本化词表按已发布职业要求匹配填写内容，过滤否定和计划语句。校验要求及经历标识，输出相关线索和缺证据提示。\
    **测试**：测试十一职业及真实填写场景，核对重复输入、无匹配、否定语句、跨范围标识和失败重试。

24. **计算可解释的证据覆盖率**  
    **指令**：采用经确认并版本化的权重与证据系数，以去重后的当前范围要求为分母，由服务端计算各类别覆盖率。  
    **测试**：手算包含直接、间接、无证据的样本并对照结果；重复要求不改变分母，空分母或样本不足时不返回百分比。

25. **展示三模块报告**  
    **指令**：以短摘要起首，依次呈现经历迁移、岗位要求与补充学习、证据覆盖率与三条优先行动。提供来源、计算说明和相关圈子入口。  
    **测试**：核对三个模块顺序、建议来源和可展开证据；样本稀少时只显示有限文字，范围为空时说明无法可靠对照，均不显示百分比。

26. **保存每个职业最新报告**  
    **指令**：保存登录用户获授权的结果及三个版本标识；按用户和职业维护最新报告，防止旧请求晚完成覆盖新结果。  
    **测试**：交错完成同职业两次分析，再分析另一职业；确认列表各职业仅一份最新结果，另一个账号无法读取，失败重做保留上一份有效结果。

## 五、分享圈子、身份与私信

27. **实现公开信息流**  
    **指令**：提供全部及十一职业的导航、关键词搜索、帖型筛选与分页。接收职业详情、报告及关联帖子传入的可清除筛选。  
    **测试**：访客组合筛选并翻页，检查无重复、无隐藏帖；从职业报告进入时预选正确职业，清除后恢复综合信息流。

28. **实现公开资料与自报身份**  
    **指令**：仅展示用户主动公开的资料和允许公开的帖子。提供在校生及已就业分享者自报设置，已就业显示「未认证」。  
    **测试**：切换资料可见性并从访客视角刷新；确认私有背景、报告和账号字段不出现在公开响应中。

29. **按角色区分发布表单**  
    **指令**：分别实现求助与经验表单，包含标题、正文、职业标签、可选附件及匿名选项。在服务端核对帖型和角色。  
    **测试**：用在校生及已就业分享者各提交合法帖型，再直接请求发布另一帖型，验证被拒绝。

30. **从读取层保护匿名身份**  
    **指令**：在信息流、详情、搜索及公开主页查询中移除匿名作者的可识别和可反查字段；保留本人管理及有审计的授权后台访问。  
    **测试**：检查公开页面和网络响应，确认匿名帖子无作者链接、标识和私信入口；普通账号无法访问作者关联，本人仍可管理。

31. **管理社区附件**  
    **指令**：区分公开配图和私有作品附件，校验类型、大小、上传权限及外链，按需签发限时访问链接。  
    **测试**：上传正常配图、超限文件和不支持类型；另一个账号无法打开私有附件，授权链接到期后不可访问。

32. **增加评论和回复**  
    **指令**：在帖子详情提供评论与回复，关联父评论，应用登录、内容校验和可见性规则。  
    **测试**：访客可读且写入会触发登录；登录后可回复公开帖，隐藏帖和跨帖父评论均拒绝写入。

33. **增加点赞与收藏**  
    **指令**：支持帖子点赞及帖子、职业收藏，按用户和目标去重，允许撤销。  
    **测试**：连续重复点击与并发请求只保留一条有效记录；撤销后计数和个人收藏同步更新。

34. **增加内容举报与风险拦截**  
    **指令**：为帖子和评论提供举报。普通内容进入发布后审核流程，高风险内容先拦截或隐藏并交人工处理。  
    **测试**：分别发布普通样本和高风险测试样本，核对公开可见性和审核队列；举报匿名帖时不向举报者透露作者。

35. **实现陌生人消息请求**  
    **指令**：从公开个人主页与非匿名帖子发起请求，提供接收、接受、拒绝及限频。  
    **测试**：从两个合法入口发起请求；待处理和拒绝状态下均无法持续发消息，第三方无法代替接收者接受。

36. **实现受控私信会话**  
    **指令**：请求接受后允许双方收发消息，提供屏蔽和举报。先使用常规刷新，按实际体验决定是否引入实时功能。  
    **测试**：验证接受后双方可对话、第三方读写被拒、屏蔽后新消息被拦截，举报仅进入授权处理入口。

## 六、个人中心与管理

37. **建立个人概览及子页导航**  
    **指令**：提供背景档案、报告、收藏、帖子、消息与账号隐私入口，访客显示登录引导。  
    **测试**：访客可返回探索；登录用户逐个进入子页，两个账号切换后不会残留彼此的私有内容。

38. **管理账号背景档案**  
    **指令**：支持五类条目和自由描述的新增、编辑、删除及跨职业复用，保存背景版本。  
    **测试**：编辑一个条目后在另一职业测评复用，删除后新测评不再读取该条目，已生成报告仍可解释其来源版本。

39. **连接个人报告、收藏、帖子和消息列表**  
    **指令**：展示报告范围、日期、版本与重做入口，支持取消收藏和管理本人内容，并区分收到、发出的请求和已有会话。  
    **测试**：逐页使用重做、取消收藏、管理匿名帖和打开会话，核对操作结果与列表一致，另一个账号访问私有链接被拒。

40. **提供社区管理员工作台**  
    **指令**：接入举报及风险队列，提供隐藏、恢复、删除、处理反馈和申诉入口。对角色变更、内容处置和受限身份查询留审计记录。  
    **测试**：用普通账号直接尝试管理操作应被拒；管理员完成隐藏及恢复后，核对前台可见性与操作者、原因、时间记录。

41. **完成账号隐私与注销**  
    **指令**：提供退出、资料可见性选择、分析数据处理告知及注销入口，落实已确认的数据保留和删除政策。\
    **测试**：用隔离账号执行注销并重新访问背景、报告、附件和会话，逐项核对失效或保留行为符合政策，错误日志不含背景原文和密钥。

## 七、发布验收

42. **验证权限矩阵**  
    **指令**：在服务端与数据层逐项覆盖访客、所有者、其他用户和管理员对档案、报告、消息、附件、审核状态和匿名身份的权限。  
    **测试**：绕过界面直接请求这些资源并更换资源标识；核对每组允许及拒绝结果，验证用户自报角色不能授予管理权限。

43. **验证移动端与无障碍**  
    **指令**：逐页检查焦点、标签、对比度、错误提示、触屏操作、减少动态效果设置及图表文字解释。  
    **测试**：分别用手机触屏和桌面纯键盘完成首页到报告；检查星系可选节点、表单按钮不被键盘遮挡、报告无横向溢出、减少动态效果设置生效。

44. **验证部署、告警和回滚**  
    **指令**：在预发布环境验证数据迁移、恢复、监控、失败告警和调用预算。记录回滚步骤与回滚后需核对的数据版本。  
    **测试**：从测试备份恢复，模拟任务超时触发告警，再回滚应用与招聘发布版本，验证旧链接、私有数据和正常请求均可用。

45. **完成全链路验收**  
    **指令**：对照设计验收 D-01 至 D-15 及设计文档引用的产品验收项，记录结果和发布阻塞。覆盖十一职业并回归其他现有专业。
